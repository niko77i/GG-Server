# 数据管理页：按可见列自动聚合 + 产品/子维度联动设计

日期：2026-10-19
状态：**待确认**
适用：GG 数据管理页（`/data-manage`）与 FB 数据管理页（`/fb/data-manage`）
前置：`2026-10-19-fb-data-manage-column-selector-design.md`（自选展示列，已实现）

---

## 1. 需求

1. **自动聚合**：隐藏维度列后（例如不要产品名、线名），列表按**当前可见的维度列**自动分组，
   数值列求和。例：只剩「日期 + 户」时，就是「每天每户」一行、消耗等合并。
2. **聚合视图只读**，并提供「放弃聚合」按钮切回明细，切回后可以编辑。
3. **产品与其子维度固定联动**：
   - FB：勾选**产品名** ⇒ 自动勾选**线名**；取消产品名 ⇒ 同时取消线名。
   - GG：勾选**产品** ⇒ 自动勾选**广告系列**；取消产品 ⇒ 同时取消广告系列。

### 已确认的决策（2026-10-19）

- 聚合规则：**按「当前可见的维度列」分组**（方案 A）。
- 聚合后：**只读**；新增「放弃聚合」按钮，放弃后按明细显示、可编辑。
- GG 的联动对：**产品 + 广告系列**。

## 3. 聚合判定

- **维度列总数** = 上表维度列的数量；**可见维度列** = 当前勾选且属于维度的列。
- **聚合生效** ⇔ `可见维度列数 < 维度列总数` **且** 用户未点「放弃聚合」。
  - 即：只要隐藏了任意一个维度列 ⇒ 自动聚合。
  - 全部维度可见 ⇒ 明细（与现状一致）。
- **聚合视图只读**：隐藏 勾选框列、行「编辑/删除」、操作列、户管的「消耗」✏️ 内联编辑。
- 「放弃聚合」按钮：**仅在聚合会生效时出现**。点击后 `aggregationOff = true` ⇒ 走明细（只显示已选列），
  按钮变为「恢复聚合」；再点恢复自动聚合。
- **列选择变化时重置 `aggregationOff = false`**（恢复按可见列自动判定的语义）。
- 聚合状态切换或可见列变化时**重置页码为 1**。

## 4. 服务端聚合（必须做在服务端）

列表是**服务端分页**（每页 50）。若在前端聚合，只能合并「当前页」⇒ 跨页的合计会错。
因此聚合下推到 SQL：

### 4.1 接口

`GET /api/fb/reports/list` 与 `GET /api/ad-reports/list` 新增可选参数：

```
group_by=report_date,product_name,account_name,...   # 逗号分隔的「列 prop」
```

- 缺省或不传 ⇒ 行为与现在**逐字不变**（明细）。
- 传了 ⇒ 按这些列分组；返回行里是**各维度列 + 各数值列的聚合值**。

### 4.2 列名白名单（安全）

`group_by` 的每个值都先经**白名单**映射到真实 SQL 列，映射不到的值直接 **400**。
**绝不允许把参数拼进 SQL**。

| FB prop → 列 | GG prop → 列 |
|---|---|
| `report_date` → `report_date` | `report_date` → `report_date` |
| `product_name` → `product_name` | `display_product` → **`product_name`**（见 §4.4） |
| `line_name` → `line_name` | `region` → `region` |
| `account_name` → `account_name` | `account` → `account` |
| `account_id` → `account_id` | `customer_id` → `customer_id` |
| — | `campaign` → `campaign` |

### 4.3 聚合表达式

- FB：`SUM(cost)`, `SUM(impressions)`, `SUM(clicks)`, `SUM(registrations)`, `SUM(purchases)`；
  `cost_per_purchase = SUM(cost) / SUM(purchases)`（分母为 0 时取 0，**不能把比率相加**）。
- GG：`SUM(cost)`, `SUM(impressions)`, `SUM(clicks)`, `SUM(installs)`, `SUM(in_app_actions)`。
- 聚合结果行**不带 `id`**（一行对应多条库记录，无法安全定位）——前端聚合态本就不展示任何写操作。
- `total` = **分组后的行数**：`SELECT COUNT(*) FROM (SELECT 1 ... GROUP BY ...)`。
- 现有筛选（产品、线名/系列、日期、保存人 `user_id`）**照常参与 WHERE**。

### 4.4 GG「产品」列的取舍（**需确认**）

明细视图里，「产品」显示的是 `resolved_product_name || product_name` —— 前者是**前端/接口层**按
`packages` 的系列前缀推断出来的展示值，**不是数据库列**，无法直接参与 `GROUP BY`。

**本设计的取舍**：聚合视图按库里的 **`product_name`** 分组与显示（不做 resolved 推断）。
理由：分组必须落在真实列上，否则同一个「推断产品」会被拆成多组、且明细与聚合口径不一致。
**明细视图的显示维持现状不变。**

> 如果你希望聚合视图也显示推断后的产品名，需要把「系列 → 产品」的解析搬进 SQL
> （或先把解析结果落库/落缓存），属于更大的改动，需要另议。

## 5. 前端改动

### 5.1 列联动

- 父列 → 子列：FB `product_name` → `line_name`；GG `display_product` → `campaign`。
- 勾父 ⇒ 自动勾子；取消父 ⇒ 同时取消子。
- 子列复选框在父列未勾选时**禁用**（避免出现「有系列没产品」的维度组合）。
- 读取旧 `localStorage` 偏好时：若含子列不含父列，**自动补上父列**（保留用户想看子列的意图）。

### 5.2 只读与「放弃聚合」按钮

- 新增 `aggregating`（是否按可见列聚合）与 `aggregationOff`（用户是否点了放弃）。
- 聚合态：隐藏勾选框列、操作列、消耗 ✏️；按钮显示「放弃聚合」。
- 放弃后：明细行（重复的 日期/户 各占一行），按钮显示「恢复聚合」，写操作恢复。

### 5.3 请求

- 聚合态：`list` 请求带 `group_by=<可见维度 prop 列表>`。
- 明细态：不带该参数（现状）。

---

## 6. 不动的东西

- **导出 CSV**：服务端导出**全部明细字段**，不受聚合/列可见性影响（延续现状）。
- 「查看统计」弹窗：走独立接口，不受影响。
- 「保存人」筛选、产品/日期筛选：照常工作。
- 后端其余端点（PUT/DELETE/batch-delete/save/retry-sync）零改动。
- 列偏好仍存 `localStorage`，不落后端。
