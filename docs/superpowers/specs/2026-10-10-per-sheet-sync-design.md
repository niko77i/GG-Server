# 按表导入 / 按表回写（TT 多表）设计

> 2026-10-10。用户验收 TT 表头映射时提出：**「表导入到系统反应有点慢，而且不管几个 sheet 都是一次性导入；
> 我想分别实现，对应的 sheet 就点对应的导入，或者刷新回表里」**。

## 一、需求与现状

**用户要的**：
1. **按表导入**（表 → 系统）：只想同步其中一张表时，点那一张即可，不必等所有表跑完。
2. **按表回写**（系统 → 表）：只想把某一张表刷新回去时，点那一张。
3. **顺带治慢**：现在每次操作都把所有表跑一遍。

**现状（已核代码）**：
- `dashboard_sync`（`py/routes/huguan_dashboard_routes.py:183-186`）`for t in tables:` **逐表读**，
  所有表的行**合并成一个列表**再进 `build_diff`；定位键校验一旦某表缺「账户ID」⇒ **整批拒**。
- `dashboard_push`（同文件 `:386-405`）对**全部表**收集 + 分组 + 写回，且每张表**多读一次表头**
  （`resolve_table_col_map`，`:396-400`）。
- 每次操作的 Sheets 往返次数 ≈ **表数 × (1 次读 + 写回/快照若干)**；push 还要 +表数 次表头读。
- 前端只有两个**平台级**按钮（「⬇️ 从表同步到系统」/「⬆️ 刷新到看板」），**没有任何按表的入口**。

## 二、已裁定的三条（用户 2026-10-10「按推荐」）

| # | 议题 | 裁定 |
|---|---|---|
| A1 | 按表同步时的去重范围 | **只在该表内去重**，不跨表。代价：同一账户同时出现在两张表时，结果取决于你点了哪张；**用库内提示补偿**（见 §3.3） |
| B | 撤回快照 | 每次**按表**操作生成该表自己的一份快照 ⇒「撤回上次」＝撤回**上一次那次操作**（点哪张撤哪张）。与「一次性全部同步」的快照不再是一回事，UI 上要说清 |
| C | tt 读范围 `A:ZZ` 收窄 | **降级为「先测再定」**：Sheets API 本就会裁掉尾部空行/空列 ⇒ 对干净的表 `A:ZZ` 读回来的就是实际宽度，收窄只在「表头右侧另有内容」时有差，且要多一次往返。**先加计时日志定位真因**，不盲改 |

## 三、技术方案

### 3.1 API：两个端点各加一个**可选** `sheet_name`

```
POST /api/huguan/dashboard/sync   {"platform":"tt", "sheet_name":"企业户", "dry_run":true, ...}
POST /api/huguan/dashboard/push   {"platform":"tt", "sheet_name":"企业户"}
```

- **`sheet_name` 缺省 ⇒ 行为与现在完全一致**（全部表）。向后兼容，前端可分批上线。
- **给了 `sheet_name`** ⇒ 只处理那一张表：
  - 校验它在该用户自己的配置里（沿用读表头端点的归属门禁口径，`routes:655-661`）——
    不在 ⇒ 400（**不得**据此读任意工作表）。
  - `platform` 仍限 tt（gg/fb 只有一张表，按表无意义）。**gg/fb 传了 `sheet_name` 一律 400**
    （用户 2026-10-10 裁定，见 §七第 1 点）：静默等同全量会让前端 bug 变哑巴。
    sync 与 push 两个端点都做这条门禁，且**在建服务/读表之前**就拒。
- **不做**新增端点：同一个端点加参数，前端两条路径共用既有响应形状。

### 3.2 后端行为变化（只在「给了 sheet_name」时）

| 环节 | 现状（全部表） | 按表 |
|---|---|---|
| 读 | 逐表读，N 次往返 | **1 次**（只读该表） |
| 定位键校验 | 任一表缺 ⇒ 整批拒 | 只校验该表；缺 ⇒ 400（文案含表名） |
| 去重 / 优先级 | 合并后**跨表**去重、靠前的表胜出 | 只有一张表 ⇒ **天然变成表内去重**（A1）＝无需新代码，只要不把别的表塞进来 |
| `unmatched_columns` | 各表分别上报 | 只含该表 |
| `sheet_from` / `sheet_back_sheets` | 反映所有表 | 只反映该表 |
| 撤回快照 | 一次操作一份（内含各表） | 一次操作一份，**只含该表**（B） |

**实现要点**：`build_diff` / `apply_diff` / `collect_rows_for_push` **一律不动** —— 按表是靠
「路由只喂一张表的数据」实现的；这样跨表去重、快照、撤回、`_account_type` 注入等既有逻辑全部原样复用，
不产生第二套路径。

### 3.3 跨表重复的提示（A1 的补偿，**只查库、不读别的表**）

按表同步时，报告里追加一节（**不含在 `diff` 的既有键里**，避免动前端契约；作为 `result` 或 `diff` 的新键
`cross_sheet_notes: [{"account_id": str, "current_type": str, "this_sheet": str}]`）：

- 判据：本次同步里出现、且**库里该账户的 `account_type` 与本次表名不同**的账户
  ⇒ 它「当前归属另一张表」，本次按表同步可能把归属/字段按这张表覆盖。
- 为什么只查库：读其它表会抵消按表带来的提速（与 A1 的初衷冲突）；库里的 `account_type` 已经是
  「上一次同步时它来自哪张表」的记账，够用。
- 条数上限（例如 50 条）+ 总数，避免报告爆掉。

### 3.4 计时日志（C 的前置，**只加日志不改行为**）

给同步与刷新各阶段打耗时，级别 `log.info`；**每次操作末尾再加一行汇总**
（范围＝全部表 / 哪张表 + 总耗时 + 行数），只记日志、不动响应形状。用户跑一两次真实
数据后，据此决定要不要做 C。**这是诊断增强，不是行为改动。**

实际落地的 tick（`routes/huguan_dashboard_routes.py` 的 `_tick`）：

| 端点 | 阶段 tick（按顺序） | 末尾汇总行 |
|---|---|---|
| sync | `建服务完成` → `读取完成` → `解析完成` → `build_diff 完成` → `落库完成` | `同步汇总`（dry_run 与落库两条返回路径各一行） |
| push | `建服务完成` → `收集完成` → `快照读完成` → `写表完成` | `刷新汇总` |

- 起表点都在 `build_service` **之前**：用户抱怨的是延迟，而「建服务 + 读表前的库操作」
  此前对所有 tick 都不可见。
- sync 的「读取 / 解析」是两个 tick：逐表读原为单循环（读文件 + 解析表头 + 逐行解析），
  现拆成两趟 —— 先读全部表并解析表头，再逐行解析 —— 才能把网络 I/O 与 CPU 解析分开
  计时；读/写/查询次数与顺序不变（缺省路径行为逐字节不变）。
  - ⚠️ **仅成功路径**：拆分后**错误路径会多几次读**（某表的 `parse_row` 抛错时，其余表的读已经发生）
    —— 单循环时代会在第一个出错行处提前中止。这是为计时付出的**已披露代价**，不是缺陷。
  - ⚠️ 另一笔代价：所有 grid **同时驻留内存**（单循环时代是逐表读完即释放）。表数与体量下有界。
  - 审查者给的更低风险替代：**不拆循环**，只在单循环后打一个「读取+解析」合并 tick ——
    代价是分不开网络 I/O 与 CPU 解析。本次选了拆分。
- `apply_diff` 之后的定向回写（`_write_background_tables`，复用其它端点的写表入口）
  未单独打 tick，其耗时体现在汇总行的总耗时里。
- push 的「快照读」只在这一端点有（写表前记原值，见 §六/规格 §6.1）。

## 四、UI 改动（TT 卡片）

- 每张表那一行右侧加两个**小按钮**：「**导入这张表**」「**刷新回这张表**」
  （与既有平台级按钮同图标语言：⬇️ / ⬆️，`size="small"`，`type="primary"`/`plain` 区分主次）。
- 平台级两个按钮文案改为「**全部导入**」「**全部刷新**」——两个层级同时存在时必须无歧义。
- **单表导入**：复用现有差异弹窗（只含该表的数据）；弹窗里「表」列恒为同一张 ⇒ **隐藏该列**；
  标题带表名（「企业户 · 差异报告」）。
- **单表刷新**：沿用现有刷新结果提示，文案带表名。
- **gg/fb 卡片不出现按表按钮**（它们只有一张表），平台级按钮文案也**不改**（保持现状，逐字节不变的口径）。
- 单表操作进行中：**只禁用该行按钮**（别的表仍可操作）——但要防并发写同一份配置/同一张表；
  实现上：进行中禁用**所有**按表按钮与平台级按钮（最简单且安全，代价是不能并发跑两张表）。
  **待确认**：是否允许并发跑两张不同的表？（推荐：**不允许**，简单且避免写回互相干扰。）

## 五、涉及的文件

| 文件 | 改动 |
|---|---|
| `py/routes/huguan_dashboard_routes.py` | sync / push 各加可选 `sheet_name`（+ 归属校验 + 只处理该表）；计时日志 |
| `py/huguan_dashboard.py` | 新增「跨表归属提示」的纯函数（输入当前解析行 + 库内 account_type，输出提示列表）；计时不改逻辑 |
| `frontend/src/components/HuguanDashboardCard.vue` | 每表两个按钮；平台级按钮改文案（tt）；单表弹窗分支（隐藏「表」列、标题带表名） |
| `py/tests/test_huguan_dashboard.py` | 按表同步/按表回滚/跨表提示/快照按表 的用例 |
| 本文件 + 实现计划 + 验收清单 | 设计 / 计划 / 清单补项 |

**数据结构**：请求体加 `sheet_name`；`diff` 或 `result` 加 `cross_sheet_notes`（新键，前端据此多显示一节）；
快照 payload **不变**（只是内容只含该表）。

## 六、非目标

- 不做「按**户类型**（表）定时自动同步」，也不做队列化/后台跑（仍然同步执行、当场返回）。
- 不改 gg/fb 的任何按钮与行为。
- 不做 C（读范围收窄），除非计时日志显示读是大头。
- 不动 `build_diff` / `apply_diff` / 写回链路的既有逻辑。
