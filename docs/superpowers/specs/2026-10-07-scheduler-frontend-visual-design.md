# 定时任务管理页：周期编辑视觉设计

> 配套设计文档：[2026-10-07-scheduler-admin-access-and-interval-config-design.md](2026-10-07-scheduler-admin-access-and-interval-config-design.md)
> 目标文件：`frontend/src/views/SchedulerView.vue`
> 日期：2026-10-07 ｜ 由 `/frontend-design` 产出

## 1. 这是什么页面，设计任务是什么

SchedulerView 是内网工具箱里 20 多个管理页之一，服务对象是各平台管理员。它**不需要**一套新的视觉身份 —— 强行换字体或色板会与相邻页面割裂。页面已有一套稳定的卡片语言：

- 卡片：`el-card shadow="never"`，纵向排列，`max-width: 800px`
- 每张卡三段：左侧 48×48 圆角 10 的 emoji 块 → 中间信息（名称/描述/tag 行）→ 右侧主动作按钮
- 文字灰阶：`#111827` 主 / `#6b7280` 次 / `#9ca3af` 弱
- 结果块：圆角 8 的浅底（绿 `#f0fdf4` / 红 `#fef2f2`）
- 唯一强调色：`#0891b2`（青），只用于「运行中」光环

**本次设计任务**：在这套既有语言内部，为「可配置周期」和「上次执行时间」两个新元素找到承载形式。**不重做页面**。

## 2. 关键判断：周期放哪

现状把频率写成只读 tag：`<el-tag>自动频率：每小时</el-tag>`。三个问题：

1. **它是错的**。TT 卡片写「每小时」，实际是 30 分钟（`_start_tt_delist_scheduler` 的 `sleep(1800)`）。本次数据驱动改造顺带修掉。
2. **只读信息里不该混进可编辑控件** —— tag 行是一排平级的胶囊，突然有一个能点，用户无法预期。
3. **周期 ≠ 元信息，也 ≠ 一次性动作**。它跟「立即执行」性质不同（长期设置 vs 单次触发），跟「启动时立即执行一次」也不同（那不是状态是说明）。

**采用方案：卡片内划一条浅分隔线，线下做「调度条」** —— 左半是周期编辑，右半是上次执行时间。

两个理由：
- **读写分离**：线上是「它现在是什么」（名称、描述、状态 tag、上次结果），线下是「你能调什么」（周期）。工具类界面的通行直觉。
- **同义聚集**：周期与上次执行都属"调度"，放一处，用户扫一眼就知道「设成多久」和「上次啥时候跑的」。

被否掉的方案：塞进 tag 行（见上）、点 tag 弹抽屉/弹窗（为两个字段开弹窗过重）。

## 4. Token（全部取自既有页面，不新增）

| 用途 | 值 |
|---|---|
| 分隔线 | `1px solid #f3f4f6`（比卡片外框更浅，层级正确） |
| 调度条说明文字（「每」「分钟」「每周」） | `13px / #6b7280`（同 `.task-desc`） |
| 「上次执行」文字 | `13px / #9ca3af`（比说明文字更弱 —— 它是辅助信息） |
| 「上次执行失败」 | `13px / #ef4444`（页面已用于掉包数字） |
| 数字对齐 | `font-variant-numeric: tabular-nums` |
| 卡片内容块间距 | `margin-top: 14px`（对齐既有 `.task-result`） |

**字体与主色一律不动**：页面乃至整个应用用 Element Plus 默认字体栈，为单独一页引入字体会与相邻页面割裂。需要"数字不跳动"时用 `tabular-nums`，**不引入 monospace 字体**。

**动效**：只保留既有的 `.task-card.running` 光环。不为分隔线、保存按钮加 hover 过渡 —— 非用户触发或纯装饰的动效不要。

## 5. 交互态

| 元素 | 态 |
|---|---|
| 周期输入框 / 下拉 | 默认；与当前值有差异时激活「保存」 |
| 「保存」按钮 | `size="small" type="primary" plain`；**无改动时 `disabled`**（这本身就是"有未保存改动"的提示）；保存中 loading |
| 保存成功 | `ElMessage.success('已保存，将在 30 秒内生效')`，并回填接口返回的全量配置 |
| 保存失败 | `ElMessage.error` 用后端 `error` 原文（后端 400 会指明字段与合法区间） |
| 输入越界 | 前端 limit 到 `min`/`max`（取自接口，不写死），后端仍兜底 400 |
| 「立即执行」 | 完全沿用现有实现与四态结果展示，**不动** |

> 「立即执行」成功后 `last_run` 会变，前端**重新拉一次 config** 刷新该行，避免显示陈旧时间。

## 6. 文案

| 位置 | 文案 |
|---|---|
| 频率（interval） | `每 [__] 分钟` |
| 频率（weekly） | `每周 [星期 ▾] [时刻 ▾]` —— 星期项「周一」…「周日」，时刻项 `00:00`…`23:00` |
| 保存按钮 | `保存` |
| 上次执行 · 今天 | `上次执行 今天 12:00:03` |
| 上次执行 · 昨天 | `上次执行 昨天 23:10:00` |
| 上次执行 · 更早 | `上次执行 10-05 00:00:02` |
| 上次执行 · 失败 | `上次执行失败（10-07 12:00:03）` |
| 从未执行 | `尚未执行` |
| 空态标题 | `当前平台暂无可管理的定时任务` |
| 空态说明 | `定时任务按平台划分：Google Ads 掉包检测与每周清理归 GG，TikTok 掉包检测归 TT。` |

**「尚未执行」与「执行失败」必须分开**：前者是 `last_run === null`，后者是 `last_run.ok === false`。合成一句「无记录」会让用户分不清是没跑过还是跑挂了。

**不用 `·` 连接失败态**（`上次执行失败 · 12:00:03`）—— 中点连接是中英混排的生成式惯用装饰，改用括号，语义更紧。
